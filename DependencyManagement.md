# Dependency Management

This project manages its dependencies using a combination of RubyGems/Bundler for Fastlane and manual integration for the Swiss Ephemeris C library.

## 1. Fastlane and RubyGems (Bundler)

Fastlane, a crucial tool for automating iOS deployment tasks, is managed through RubyGems and Bundler. This ensures that all developers work with the same versions of Fastlane and its plugins, preventing compatibility issues.

*   **`Gemfile`**: This file lists all the RubyGems dependencies required by Fastlane. It specifies Fastlane itself and any Fastlane plugins used in the project.
    ```ruby
    # Example Gemfile content
    source "https://rubygems.org"

    gem "fastlane"
    # Add any Fastlane plugins here, e.g.:
    # gem "fastlane-plugin-firebase_app_distribution"
    ```

*   **`Gemfile.lock`**: This file is automatically generated by Bundler (`bundle install`). It records the exact versions of all gems (including transitive dependencies) that were installed. This ensures reproducible builds across different environments.

### How to Install/Update Fastlane Dependencies

1.  **Install Bundler (if you don't have it):**
    ```bash
    gem install bundler
    ```

2.  **Navigate to the project root:**
    ```bash
    cd /path/to/your/vyasfather
    ```

3.  **Install/Update gems:**
    ```bash
    bundle install
    ```
    This command reads the `Gemfile`, installs all listed gems (if not already present), and updates `Gemfile.lock` if new gems are added or versions are updated.

4.  **Execute Fastlane commands:**
    Always prefix Fastlane commands with `bundle exec` to ensure you're using the versions specified in `Gemfile.lock`:
    ```bash
    bundle exec fastlane beta
    ```

## 2. Swiss Ephemeris (C Library Integration)

The Swiss Ephemeris is a high-precision ephemeris library written in C, used for astrological calculations. It is integrated into this Swift project manually.

*   **`ThirdParty/SwissEph/src/`**: This directory contains the source code files (`.c` and `.h`) of the Swiss Ephemeris library.

*   **Building the Static Library**: The GitHub Actions workflow (`.github/workflows/ios-appstore-upload-v3.yml`) includes a step to compile these C source files into a static library (`libswe.a`):
    ```yaml
    - name: Build Swiss Ephemeris static library
      run: |
        set -euo pipefail
        SRC_DIR="ThirdParty/SwissEph/src"
        mkdir -p ThirdParty/SwissEph/lib
        pushd "$SRC_DIR" >/dev/null
        SDK=$(xcrun --sdk iphoneos --show-sdk-path)
        CC=$(xcrun --sdk iphoneos -f clang)
        CFLAGS="-arch arm64 -isysroot $SDK -O2 -fembed-bitcode -I."
        OBJS=()
        for c in swe*.c swem*.c sweh*.c; do
          # exclude test program if present
          if [ "$c" = "swetest.c" ]; then continue; fi
          echo "Compiling $c"; "$CC" $CFLAGS -c "$c" -o "${c%.c}.o"
          OBJS+=("${c%.c}.o")
        done
        echo "Creating libswe.a"; libtool -static -o libswe.a "${OBJS[@]}"
        mv libswe.a ../lib/
        popd >/dev/null
    ```
    This step compiles the necessary `.c` files for the iOS platform (arm64 architecture) and creates `libswe.a` in `ThirdParty/SwissEph/lib/`.

*   **Bridging to Swift**: The C functions from Swiss Ephemeris are made accessible to Swift code through a bridging header and wrapper files:
    *   **`NotesApp/SwissEphBridge.h`**: This is the Objective-C bridging header. It exposes the necessary C function declarations from the Swiss Ephemeris library to the Objective-C runtime, which Swift can then interact with.
    *   **`NotesApp/SwissEphWrapper.m`**: This Objective-C wrapper file provides a thin layer of Objective-C code that calls the underlying C functions from Swiss Ephemeris. This wrapper simplifies the interface for Swift, making it more idiomatic to call these functions from Swift code.

This manual integration ensures tight control over the Swiss Ephemeris library and its compilation for the target platform.
